## ADR-001：数据归属

### 问题

训练数据是每个用户私有、配对双方共享、还是私有但允许显示对方概要？

### 决策

**每个 openid 独立拥有训练数据，不与配对共享。**

### 选择理由

1. **需求差异**：两人健身目标、动作库、训练强度通常不同
2. **隐私边界**：训练记录比饮食更私密，避免互相可见
3. **简化模型**：MVP 阶段无需复杂的共享权限
4. **现有对比**：饮食数据按 `pairId` 共享是因为"一起吃"场景；训练无此场景

### 被拒绝的方案

| 方案 | 拒绝原因 |
|------|----------|
| 配对共享所有训练数据 | 过度暴露，两人训练计划不同 |
| 私有 + 概要可见 | MVP 过于复杂，后续版本可扩展 |

### 影响

- 所有训练集合的权限设置为 `creator` 可读写
- 查询条件使用 `openid`，不使用 `pairId`
- 未配对用户也可使用训练功能

## ADR-002：模板生效时间

### 问题

1. 首次创建模板后，当前周是否立即生成？
2. 修改模板后从当前周还是下周一生效？
3. 已生成的周计划是否保持不变？
4. 周一到周日如何计算？

### 决策

| 场景 | 行为 |
|------|------|
| 首次创建模板 | **立即生成当前周**（用户期望立刻使用） |
| 修改模板 | **从下一周一生效**，当前周保持不变 |
| 已生成的历史周 | **永不被模板回写** |
| 一周定义 | **周一 00:00:00 ~ 周日 23:59:59**（ISO 周） |

### 选择理由

1. **首次立即生效**：避免用户创建模板后看到空白页，体验差
2. **修改下周生效**：防止用户当周打卡进度被意外重置
3. **历史不可变**：快照保证数据完整性
4. **周一起始**：符合中国健身用户习惯，与 `getDay()` 调整（0=周日 → 7）

### 被拒绝的方案

| 方案 | 拒绝原因 |
|------|----------|
| 首次也等下周一 | 用户等待时间长，体验差 |
| 修改立即覆盖当前周 | 已打卡数据被重置，用户困惑 |
| 周日起始 | 不符合中国用户习惯 |

### 影响

- 周计划需存储 `templateVersion` 或 `snapshotAt` 字段
- 生成逻辑需判断当前周是否已存在

## ADR-003："+1" 打卡语义

### 问题

需求中出现了"组数"、"每组次数"、"`0/8 10kg`"、"每点击一次 +1"。`+1` 代表什么？

### 决策

**`+1` 代表完成一组（set），而非单次重复（rep）。**

### 示例

| 计划 | 目标 | 用户操作 | 数据变化 |
|------|------|----------|----------|
| 深蹲 3×12 | 3 组，每组 12 次 | 点击 3 次 `+1` | `completedSets: 0 → 1 → 2 → 3` |
| 卧推 4×8 @60kg | 4 组，每组 8 次，60kg | 点击 4 次 | 每次可单独记录实际重量 |

### 详细规则

1. **显示格式**：`{completedSets}/{targetSets}` + 当前重量，如 `2/3 60kg`
2. **点击行为**：
   - 默认：`completedSets += 1`，使用计划重量
   - 长按或展开：可修改本组实际重量
3. **进度锁定**：`completedSets >= targetSets` 时，`+1` 按钮禁用，显示 ✓
4. **云写入**：使用 `db.command.inc(1)` 原子自增，避免并发问题
5. **撤销**：MVP 不支持撤销，防止误操作（后续可加 `-1`）

### 选择理由

1. **点 36 次不现实**：3×12 点 36 次，用户不可能接受
2. **组是最小记录单位**：健身习惯以组为单位记录
3. **重量按组记录**：同一动作不同组可能递增/递减重量

### 被拒绝的方案

| 方案 | 拒绝原因 |
|------|----------|
| +1 = 1 次 rep | 点击次数过多，体验极差 |
| +1 = 完成整个动作 | 无法记录组数进度 |

### 数据结构影响

```json
{
  "exerciseId": "...",
  "targetSets": 3,
  "targetReps": 12,
  "targetWeight": 60,
  "completedSets": 2,
  "setDetails": [
    { "weight": 60, "reps": 12, "completedAt": "2026-07-09T10:30:00Z" },
    { "weight": 62.5, "reps": 10, "completedAt": "2026-07-09T10:35:00Z" }
  ]
}
```

## ADR-004：周计划生成机制

### 问题

周计划应该如何生成？

1. 定时云函数提前生成
2. 用户打开训练页时懒生成
3. 每次查询时临时计算，不保存

### 决策

**用户打开训练页时懒生成（Lazy Generation）。**

### 生成流程

```
用户打开训练页
    ↓
查询当前周计划（weekId = getWeekId(today)）
    ↓
存在？→ 直接返回
    ↓
不存在 → 查询用户模板
    ↓
模板存在？→ 生成周计划快照 → 写入数据库 → 返回
    ↓
模板不存在 → 返回空，提示创建模板
```

### 幂等规则

| 要素 | 方案 |
|------|------|
| 唯一键 | `openid + weekId`，weekId 格式 `2026-W28` |
| 防重复 | 查询前先 `where({ openid, weekId }).get()`，存在则跳过 |
| 并发锁 | 前端加 loading 锁，同一 openid 同时只能触发一次生成 |
| 数据库层 | 建立 `{ openid: 1, weekId: 1 }` 唯一索引（推荐） |

### 选择理由

1. **无需定时函数**：减少云函数调用成本
2. **按需生成**：用户不打开训练页则不消耗资源
3. **快照保证历史不变**：周计划是模板的深拷贝

### 被拒绝的方案

| 方案 | 拒绝原因 |
|------|----------|
| 定时云函数提前生成 | 增加维护成本，用户可能未使用 |
| 不保存，每次计算 | 无法保留历史快照，修改模板会影响历史 |

### weekId 计算

```js
/**
 * 获取 ISO 周标识，如 2026-W28
 * @param {Date} date
 * @returns {string}
 */
function getWeekId(date) {
  const d = new Date(Date.UTC(date.getFullYear(), date.getMonth(), date.getDate()))
  const dayNum = d.getUTCDay() || 7  // 周日 = 7
  d.setUTCDate(d.getUTCDate() + 4 - dayNum)  // 调整到周四
  const yearStart = new Date(Date.UTC(d.getUTCFullYear(), 0, 1))
  const weekNo = Math.ceil((((d - yearStart) / 86400000) + 1) / 7)
  return `${d.getUTCFullYear()}-W${String(weekNo).padStart(2, '0')}`
}
```

## ADR-005：教学视频归属

### 问题

教学视频链接应关联到哪个层级？

- 固定动作库
- 自定义动作
- 模板项目
- 周计划项目

### 决策

**教学视频关联到"自定义动作"层级，随快照复制到周计划。**

### 继承规则

```
固定动作库（预设 3 条视频链接，只读）
    ↓ 用户选择
模板项目（继承固定动作的链接，用户可覆盖添加/删除）
    ↓ 生成快照
周计划项目（深拷贝模板项目的链接，历史不变）
```

### 详细设计

1. **固定动作**：预设视频链接（如官方教程），用户只读
2. **自定义动作**：用户自定义动作时可添加链接
3. **模板项目**：创建模板时，链接从动作继承，用户可覆盖
4. **周计划项目**：生成时深拷贝 `videoLinks[]`，与模板解耦
5. **修改规则**：
   - 修改模板视频 → 只影响下周生成的计划
   - 修改动作库视频 → 需用户手动同步到模板
   - 周计划视频 → **MVP 不可编辑**（简化）

### 被拒绝的方案

| 方案 | 拒绝原因 |
|------|----------|
| 只存动作库 ID，运行时查询 | 模板修改会影响历史 |
| 周计划可编辑视频 | MVP 过于复杂 |

### 微信小程序外链限制

| 链接类型 | 可否打开 | 方案 |
|----------|----------|------|
| 小程序内页 | ✅ | `wx.navigateTo` |
| 微信公众号文章 | ✅ | `wx.navigateTo` 带 url 或 `web-view` |
| 外部 HTTPS | ⚠️ | 需 `web-view` + 业务域名白名单 |
| 外部 HTTP | ❌ | 不支持 |
| 抖音/B站/YouTube | ⚠️ | 需白名单，否则降级为复制链接 |

### 降级方案

```js
function openVideoLink(url) {
  // 1. 尝试 web-view（需白名单）
  // 2. 失败则复制链接到剪贴板
  wx.setClipboardData({
    data: url,
    success: () => wx.showToast({ title: '链接已复制，请在浏览器打开', icon: 'none' })
  })
}
```

## ADR-006：MVP 页面架构

### 决策

**MVP 使用 3 个页面 + 1 个组件。**

| 页面 | 路径 | 职责 |
|------|------|------|
| 训练首页 | `pages/training/training` | 当前周计划、打卡、历史周入口 |
| 模板编辑 | `pages/training-template/training-template` | 创建/编辑每周模板 |
| 动作选择 | `pages/training-exercise/training-exercise` | 选择固定动作或创建自定义动作 |

| 组件 | 路径 | 职责 |
|------|------|------|
| 训练项目 | `components/exercise-item/exercise-item` | 单个训练项目的打卡卡片 |

### 页面详情

#### 1. 训练首页（training）

| 项目 | 内容 |
|------|------|
| **路径** | `pages/training/training` |
| **职责** | 展示当前周计划、打卡进度、周切换、历史入口 |
| **入口** | tabBar 第 3 项 |
| **主要状态** | `weekId`, `weekDays[]`, `selectedDay`, `exercises[]`, `loading` |
| **加载状态** | 骨架屏或 loading 提示 |
| **空状态** | 无模板 → 引导创建；当日无训练 → 显示休息提示 |
| **错误状态** | `wx.showToast` + 重试按钮 |
| **主要操作** | 切换日期、+1 打卡、修改重量、查看视频、编辑模板、切换历史周 |
| **复用样式** | `.card`, `.primary-btn`, `--color-primary` |
| **新组件** | `exercise-item` |

#### 2. 模板编辑页（training-template）

| 项目 | 内容 |
|------|------|
| **路径** | `pages/training-template/training-template` |
| **职责** | 编辑周一至周日的训练安排 |
| **入口** | 训练首页右上角"编辑模板" |
| **主要状态** | `template`, `selectedDay`, `exercises[]`, `unsaved` |
| **加载状态** | loading |
| **空状态** | 每日为空时显示"添加动作"按钮 |
| **错误状态** | 保存失败提示 |
| **主要操作** | 选择日期、添加动作、设置组数/次数/重量、删除动作、保存 |
| **复用样式** | `.card`, `.primary-btn` |
| **新组件** | 无（复用 `exercise-item` 简化版） |

#### 3. 动作选择页（training-exercise）

| 项目 | 内容 |
|------|------|
| **路径** | `pages/training-exercise/training-exercise` |
| **职责** | 从固定库选择或创建自定义动作 |
| **入口** | 模板编辑页"添加动作" |
| **主要状态** | `category`, `exercises[]`, `customExercises[]`, `searchKeyword` |
| **加载状态** | loading |
| **空状态** | 搜索无结果时提示"创建自定义动作" |
| **错误状态** | 加载失败提示 |
| **主要操作** | 搜索、选择动作、创建自定义动作、管理视频链接 |
| **复用样式** | `.card`, 列表样式 |
| **新组件** | 无 |

#### 4. exercise-item 组件

| 项目 | 内容 |
|------|------|
| **路径** | `components/exercise-item/exercise-item` |
| **职责** | 展示单个训练项目，支持打卡 |
| **属性** | `exercise`, `editable`, `checkable` |
| **事件** | `bind:check`, `bind:edit`, `bind:video` |
| **复用样式** | `.card`, `--color-primary`, `--color-success` |

### 视频管理

**不单独设页，使用页面内半屏弹层（`wx.showActionSheet` + 自定义区域）。**

| 操作 | 交互 |
|------|------|
| 查看视频 | 点击动作卡片 → 展开视频列表 |
| 添加视频 | 动作选择页 / 模板编辑页内，输入链接 |
| 编辑/删除 | 长按视频项 → ActionSheet |

## 关键流程图

### 流程 1：首次创建模板并生成当前周

```
用户打开训练页（无模板）
    ↓
显示空状态："尚未创建训练计划"
    ↓
点击"创建模板"
    ↓
跳转模板编辑页
    ↓
选择周一 → 添加动作（深蹲 3×12）
    ↓
保存模板（写入 trainingTemplates）
    ↓
返回训练首页
    ↓
检测到模板存在 + 当前周计划不存在
    ↓
生成当前周计划快照（写入 trainingWeeks）
    ↓
显示当前周计划
```

### 流程 2：修改模板

```
用户在训练首页点击"编辑模板"
    ↓
跳转模板编辑页，加载当前模板
    ↓
修改周三训练内容
    ↓
保存模板（更新 trainingTemplates，version++）
    ↓
显示提示："模板已更新，将从下周一生效"
    ↓
返回训练首页
    ↓
当前周计划保持不变（快照隔离）
```

### 流程 3：跨周首次打开

```
用户在周二打开训练页
    ↓
查询当前周计划（weekId = 2026-W28）
    ↓
不存在 → 查询模板
    ↓
模板存在 → 生成新周计划
    ↓
显示新周计划
```

### 流程 4：+1 打卡

```
用户点击"深蹲"卡片的 +1 按钮
    ↓
前端乐观更新 UI（completedSets + 1）
    ↓
调用 API：incrementCheckin(weekId, dayIndex, exerciseIndex)
    ↓
云数据库原子更新：db.command.inc(1)
    ↓
成功 → 保持 UI
失败 → 回滚 UI + 显示错误
```

## 日期与时区规范

| 项目 | 规范 |
|------|------|
| 日期格式 | `YYYY-MM-DD`（如 `2026-07-09`） |
| 周标识格式 | `YYYY-Www`（如 `2026-W28`） |
| 时区 | **中国标准时间（UTC+8）** |
| 一周起始 | **周一**（ISO 周） |
| 时间戳 | 云数据库 `new Date()` 自动使用服务器时间 |
